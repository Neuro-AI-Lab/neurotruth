## 1. 영상에서 전달할 한 문장

**NeuroTruth는 Watch 생체신호에서 갈망 가능성의 변화를 기록하고, 사용자가 원할 때 자기설문과 대화를 이어갈 수 있도록 돕는 연구용 보조 시스템입니다.**

다음 표현은 사용하지 않습니다.

- “갈망을 진단했습니다”, “알코올사용장애입니다”
- “대화 후 갈망이 감소했습니다”
- “CBT로 치료되었습니다”, “회복되었습니다”
- “앱이 위험을 예방했습니다”
- 대화·알림과 이후 기록 변화 사이의 인과관계

대신 다음처럼 설명합니다.

- “연구용 모델이 네 단계 중 하나로 표시합니다.”
- “최근 120일 동안 기록된 단계 구성을 확인합니다.”
- “당시 사용자가 남긴 자기설문과 대화 기록입니다.”
- “날짜와 상황에 따라 기록이 달라지는 모습을 보여줍니다.”

## 2. 가상 사용자와 120일 서사

### 공개용 페르소나

- 이름: 정우식 **(가명·가상 사용자)**
- 연령/직업: 51세, 식당 운영
- 사용 배경: 식당 마감과 운영 스트레스가 이어지는 저녁에 술 생각이 자주 떠올라, 그 순간을 기록하고 대화로 정리하기 위해 앱을 사용
- 대화 어조: 한국어 해요체, 담담하고 구체적이며 과장하지 않음
- 영상에서 보여주지 않을 정보: 주소, 전화번호, 실제 계정 비밀번호, 서버 주소, 토큰, API 키

### 120일 기록의 해석

데이터는 한 방향으로 좋아지는 곡선이 아닙니다. 네 구간 모두 등장하고, 식당 운영 시간·주말·업무 스트레스에 따라 오르내립니다.

최근 1시간은 `Alcohol_Test`의 메인 데모 시나리오
`NT-DP-002 / 1_1_010_V1`에서 가져온 360개 갈망 확률을 10초 간격으로
표시합니다. 기존 MA10 값과 순서, 60분 시간축 정규화를 그대로 유지해
**깊은 저점 뒤 빠르게 반등하고 높은 구간이 이어지는 형태**를 보여줍니다.
이는 VP-012의 실제 측정값이 아니라 실제 모델 곡선 형태를 이용한 데모용
시계열입니다.

완료된 과거 날짜는 아침·점심·저녁의 Watch 착용 구간만 대시보드에
표시합니다. 측정된 시간은 10초 측정 축에 맞춰 시간당 360개이며, 미측정
시간은 빈 구간으로 남습니다. 저장 공간을 불필요하게 늘리지 않기 위해 15분
대표값 하나가 10초 측정 90개를 나타내며, 이 환산은 가상 데모 행에만
적용됩니다. 120일 안에는 실제 알림 규칙인 `위험 3회 연속`을 충족하는
갈망 이벤트가 날짜별 2~10건 범위에서 재현 가능한 무작위 시각으로
분산되어 있습니다. 각 이벤트에는 AUQ 자기설문 기록이 연결됩니다.
이벤트 날짜에는 Watch 착용 구간의 `위험` 구간이 표시되어 일·주·월 단계
막대에서도 구분할 수 있습니다.

| 구간 | 화면에서 설명할 맥락 | 금지되는 해석 |
|---|---|---|
| 120–91일 전 | 늦은 마감이 있는 저녁에 `주의·위험` 기록이 군집하고, 다른 날에는 `안정·관찰`도 나타남 | “초기 중증 상태” |
| 90–61일 전 | 주말과 바쁜 영업일에 기록이 늘지만 일정한 상승·하락 추세는 없음 | “상태가 악화됨” |
| 60–31일 전 | 자기설문과 대화 사용 횟수가 달라지며 갈망 단계도 계속 변동 | “앱 사용으로 개선됨” |
| 최근 30일 | 일·주·월 화면에서 네 단계와 이벤트가 섞여 보이고, 최근 1시간은 촬영일의 기록을 보여줌 | “치료 효과가 확인됨” |

더미 데이터는 대시보드 시연용입니다. 120일 연속 원시 PPG/EDA, 얼굴 영상, STT 음성 또는 rPPG 파형을 만들지 않습니다. 실시간 신호와 선택 rPPG 장면은 실제 기기·실제 서비스 동작을 촬영합니다.

## 3. 촬영 전 준비

### 데이터와 서버

- [ ] 백엔드 `/health`, `/ready`, `/model/status`가 정상이다.
- [ ] 촬영 당일 서울 날짜를 `--anchor-date`로 사용해 `--dry-run` 후 seed했다.
- [ ] `--status`의 로그인 ID가 `woosik.jeong@neurotruth.kr`이고 날짜 범위와 건수가 예상과 맞다.
- [ ] 비밀번호는 `DEMO_PATIENT_PASSWORD`로만 전달했고 화면 녹화·쉘 기록에 남기지 않았다.
- [ ] 가상 계정으로 로그인되며 다른 사용자 기록이 보이지 않는다.
- [ ] 최근 1시간이 저점 뒤 반등하는 `1_1_010_V1` 곡선으로 보이며, 임의의 7구간 파형이나 선 그래프로 표시되지 않는다.
- [ ] 촬영 시작 전에 활성 대화 세션이 남아 있지 않다. 신규 진입에서 자기설문 화면이 필요하기 때문이다.

### Phone과 Watch

- [ ] 최신 Phone/Watch debug APK가 설치되어 있다.
- [ ] Phone과 Watch가 페어링되어 있고 Watch 앱 권한과 Samsung Health 개발자 모드가 준비되어 있다.
- [ ] Phone 알림·생체신호·AI 분석 동의가 켜져 있다.
- [ ] Phone과 Watch의 시간·날짜·시간대가 `Asia/Seoul`로 일치한다.
- [ ] 개인 알림, 연락처 이름, Wi-Fi SSID, 디버그 오버레이를 숨겼다.
- [ ] Phone은 세로 화면 녹화, Watch는 별도 카메라 또는 ADB 캡처로 녹화한다.

### 반드시 지킬 사실성 규칙

1. 실제 앱에 없는 화면이나 팝업을 편집으로 합성하지 않습니다.
2. 갈망 알림은 서버가 실제 `watch_sensor` 기록을 판정해 생성한 경우에만 알림 장면으로 사용합니다.
3. `DEMO_SCENARIO_ENABLED=true`인 예약 계정에서는 fresh login 뒤 첫 다섯 Watch 결과가 `관찰 → 주의 → 위험 → 위험 → 위험`으로 진행됩니다. 실제 센서 창은 그대로 암호화 저장되며 세 번째 위험 결과는 기존 서버 알림 규칙으로 판정됩니다.
4. 알림은 측정 시작 약 60초 뒤 예상하지만 통신 지연을 고려해 90초까지 원본 영상을 유지합니다. 재현하지 못하면 가짜 알림을 만들지 않고 대시보드의 **가상 기록 내 갈망 이벤트**와 챗봇 직접 진입 대체 컷을 사용합니다.
5. 영상 속 모델 응답은 실제 Bedrock 응답을 촬영합니다. 아래의 사용자 발화만 페르소나 대본으로 고정합니다.
6. Watch 측정 중에는 카메라 측정 버튼이 비활성입니다. 선택 rPPG 컷은 Watch 측정을 중지하고 연결 해제가 확인된 뒤 별도로 촬영합니다.

## 4. 110초 권장 편집본

각 장면은 실제 기기에서 길게 촬영한 뒤 아래 시간으로 편집합니다. 20초 warm-up과 20초 rPPG 촬영을 임의의 가짜 진행률로 바꾸지 말고, 점프 컷에는 `실제 측정 진행 중 · 화면 일부 생략` 자막을 넣습니다.

| 최종 시간 | 화면/구도 | 정확한 기기 조작 | 내레이션 | 화면 자막 |
|---:|---|---|---|---|
| 0–6초 | 타이틀 + Phone/Watch 실물 | 조작 없음 | “NeuroTruth는 갈망 상황의 기록과 대화를 돕는 연구용 보조 시스템입니다.” | `DEMO · FICTIONAL DATA` / `진단·치료를 대신하지 않습니다` |
| 6–14초 | Phone 로그인 후 홈 | 가상 계정으로 로그인 → 홈 확인. 비밀번호 입력 장면은 자름 | “가상의 식당 운영자 정우식 씨가 최근 120일 동안 사용한 상황을 구성했습니다.” | `정우식(가명) · 최근 120일 가상 기록` |
| 14–27초 | 홈의 Watch 카드 + Watch 화면 | Phone 홈에서 `측정 시작` → Watch가 확인을 요구하면 Watch 알림 1회 탭 → Phone의 `측정·자동 전송 중`과 Watch 측정 상태 확인 | “측정 시작은 휴대폰에서 요청하고, Watch가 수집을 시작하면 데이터가 자동으로 서버에 전달됩니다.” | `20초 수집 · 이후 10초마다 최신 구간 분석` |
| 27–38초 | Phone 대시보드 실시간 신호와 최근 1시간 | 하단 `대시보드` → `실시간 신호`의 PPG·EDA → `최근 1시간 변화` 순서로 천천히 스크롤 | “실시간 PPG와 EDA를 확인하고, 최근 한 시간의 기록은 안정·관찰·주의·위험 단계로 살펴봅니다.” | `연구용 4단계 표시` / `누락 구간은 연결하지 않음` |
| 38–48초 | Phone·Watch 알림 또는 대체 컷 | **실제 알림이 생성된 경우에만** 양쪽 알림을 촬영하고 Phone에서 `지금 대화하기` 탭. 재현되지 않으면 대시보드 `갈망 이벤트` → 하단 `챗봇` 탭 | “Watch의 위험 단계가 20초 이내 간격으로 세 번 연속 기록되면 한 번 알리고, 15분 동안 추가 알림을 보내지 않습니다.” | 실제 알림: `Phone·Watch 동일 이벤트` / 대체 컷: `가상 데이터에 기록된 갈망 이벤트` |
| 48–63초 | 자기설문과 결과 | 신규 세션의 `자기설문`에서 정보 아이콘을 짧게 확인 → 8문항 응답은 2–3개 선택 컷으로 압축 → `결과 확인` → `총점 X/48` → `챗봇으로 이동` | “대화를 시작하기 전, 사용자는 AUQ를 참고한 8문항 자기설문을 작성하거나 건너뛸 수 있습니다.” | `연구용 한국어 adaptation` / `결과는 진단이 아닙니다` |
| 63–84초 | AI 챗봇 | 첫 사용자 문장을 텍스트로 전송 → 실제 AI 답변 표시 → 두 번째 문장은 마이크로 녹음·전송 → 해당 AI 답변의 자동 TTS를 실제로 재생 | “텍스트와 음성 중 편한 방식을 고를 수 있습니다. 음성은 글로 변환된 뒤 바로 전송되고, 해당 답변은 음성으로 들려줍니다.” | `자유대화 · 질문 순서 없음` / `AI 응답은 실제 서비스 결과` |
| 84–101초 | 대시보드 일·주·월 | 대화 `종료` → 하단 `대시보드` → 일간, 주간, 월간을 차례로 선택. 최근 1시간, 갈망 이벤트, 자기설문 영역을 보여줌 | “대시보드는 최근 한 시간과 일간·주간·월간 기록을 함께 보여줍니다. 변화는 사실 그대로 제시하며 원인을 단정하지 않습니다.” | `최근 120일 가상 데이터` / `측정 없음과 이벤트 0건을 구분` |
| 101–110초 | 엔딩: Phone 홈 + Watch | 홈으로 돌아가 현재 단계와 Watch 상태를 함께 잡음 | “NeuroTruth는 사용자가 갈망의 순간을 기록하고 대화를 시작할 수 있도록 보조합니다.” | `연구용 보조 시스템` / `의료행위·진단·응급 대응을 대체하지 않습니다` |

### 90초 편집이 필요한 경우

- 27–38초를 7초로 줄입니다.
- 자기설문은 첫 문항, 마지막 문항, 결과만 각 2초씩 사용합니다.
- 일·주·월은 각 2초씩 보여줍니다.
- 필수 고지 0–6초와 101–110초 문구는 줄이거나 제거하지 않습니다.

### 120초 편집이 가능한 경우

- 27–38초에 Watch 최근 1시간 화면을 3초 추가합니다.
- 63–84초의 실제 AI 응답과 TTS를 잘리지 않게 재생합니다.
- 84–101초에서 월간 네 단계 구성과 AUQ 기록을 각각 3초 더 보여줍니다.

## 5. VP-012 사용자 발화 대본

AI의 문장은 미리 합성하지 않고 실제 응답을 사용합니다. 응답이 진단·처방·치료 효과를 단정하거나 화면에 부적절한 개인정보를 포함하면 그 테이크를 폐기하고 새 세션에서 다시 촬영합니다.

### 텍스트 입력

> 식당 마감이 늦어지면 스트레스를 받아서 술 생각이 많이 나요. 오늘도 그런 날이었어요.

### STT 입력

> 한 번 마시기 시작하면 멈추기가 어려워요. 오늘은 술 말고 다른 방법으로 넘기고 싶어요.

### 추가 대화가 필요할 때

> 몇 번 줄여보려고 했는데 의지만으로는 잘 안 되더라고요.

> 집사람이 걱정을 많이 해서 미안한 마음도 있어요.

### AI 응답 방향

대화는 고정 문진을 채우는 방식이 아니라 다음 순서만 약한 가이드로 사용합니다.

1. 사용자가 말한 갈망 상황과 감정을 짧게 반영합니다.
2. 사용자가 지금 원하는 도움을 확인합니다.
3. 한 번에 하나의 작고 실행 가능한 선택지를 함께 고릅니다.
4. 실행 후 달라진 점을 단정하지 않고 확인합니다.
5. 종료할 때는 촉발 상황과 사용자가 선택한 행동을 중립적으로 정리합니다.

예시:

> 사용자: 식당 마감 시간이 가까워지니까 술 생각이 자꾸 나요.
>
> AI: 마감 무렵 긴장과 피로가 겹치면서 술 생각이 커졌군요. 지금은 마음을 가라앉히는 것과 상황에서 잠시 거리를 두는 것 중 어느 쪽이 더 필요할까요?
>
> 사용자: 일단 이 시간을 넘기고 싶어요.
>
> AI: 좋아요. 지금 가능한 작은 방법 하나만 골라볼게요. 술이 있는 곳에서 잠시 떨어지거나, 물을 마시며 10분 기다리거나, 믿는 사람에게 짧게 연락하는 방법 중 가능한 게 있을까요?

같은 질문 반복, 추궁, 훈계, 진단·처방, 갈망 감소나 치료 효과의 단정은 사용하지 않습니다.

### 안전 질문이 실제로 나온 경우에만

> 아니요, 지금 다치거나 위험한 상황은 전혀 없어요. 술 생각이 나는 상황을 이야기하고 싶어요.

이 발화를 위험 질문을 유도하기 위한 첫 문장으로 사용하지 않습니다. 이 가상 페르소나는 자살·자해 맥락을 데모 소재로 사용하지 않습니다.

## 6. 선택 rPPG 삽입 컷

rPPG는 핵심 Watch 흐름과 분리된 선택 기능입니다. 최종 러닝타임이 허용될 때 8–12초만 삽입합니다.

### 촬영 순서

1. Phone에서 `측정 중지`를 누르고 Watch가 중지되었는지 확인합니다.
2. Watch 연결 해제가 앱에서 확정될 때까지 기다립니다.
3. 홈의 `카메라로 측정`이 활성화된 실제 화면을 녹화합니다.
4. 버튼 탭 → 전면 카메라에서 얼굴 1초 안정화 → 실제 20초 촬영을 수행합니다.
5. 업로드·분석 완료 화면과 챗봇 이동을 촬영합니다.
6. 편집 시 촬영 시작 2초, `실제 20초 측정 · 중간 생략` 점프 컷, 분석 상태 2초만 사용합니다.

### 삽입 내레이션

“Watch를 사용하지 않을 때는 선택적으로 얼굴 영상을 측정할 수 있습니다. 영상 분석 결과도 연구용 모델 기록이며, 의료적 판정이 아닙니다.”

### 금지

- 사전 제작한 얼굴 영상이나 다른 사람의 영상을 실제 측정처럼 업로드하지 않기
- 품질 미달을 낮은 갈망으로 설명하지 않기
- rPPG 결과가 Watch 알림을 발생시킨다고 설명하지 않기
- Watch가 연결된 상태에서 카메라 버튼이 활성화된 것처럼 합성하지 않기

## 8. 내레이션·자막 원고

### 연속 내레이션

> NeuroTruth는 갈망 상황의 기록과 대화를 돕는 연구용 보조 시스템입니다. 이 영상은 가상 사용자와 최근 120일의 더미 데이터를 사용합니다. 측정 시작은 휴대폰에서 요청하고, Watch가 수집을 시작하면 데이터가 자동으로 서버에 전달됩니다. 실시간 PPG와 EDA를 확인하고, 갈망 가능성은 안정, 관찰, 주의, 위험의 네 단계로 표시합니다. Watch의 위험 단계가 20초 이내 간격으로 세 번 연속 기록되면 휴대폰과 Watch에서 같은 알림을 확인할 수 있으며, 추가 알림은 15분 동안 제한됩니다. 사용자는 AUQ를 참고한 자기설문을 작성하거나 건너뛴 뒤 자유대화를 시작할 수 있습니다. 텍스트와 음성 입력을 모두 지원하며, 음성으로 보낸 메시지의 답변은 TTS로 들을 수 있습니다. 대시보드는 최근 한 시간과 일간, 주간, 월간 기록을 보여줍니다. 이 변화는 기록의 차이를 설명할 뿐, 진단이나 치료 효과를 의미하지 않습니다.

### 필수 고정 자막

- 오프닝: `가상 사용자 · 최근 120일 더미 데이터`
- 데이터 화면 좌상단 또는 우상단: `DEMO / FICTIONAL DATA`
- 갈망 단계 화면: `연구용 모델 출력 · 진단 아님`
- 자기설문 결과: `연구용 한국어 adaptation · 임상 판정 아님`
- 엔딩: `의료행위·진단·응급 대응을 대체하지 않습니다`

## 9. 연속성·사실성 검수

### 화면 연속성

- [ ] 모든 역사 화면의 선택 날짜가 seed 범위 안이고 미래 날짜가 아니다.
- [ ] 일간 → 주간 → 월간의 기준 날짜가 같은 촬영일을 가리킨다.
- [ ] 최근 1시간과 홈의 최신 측정 시각이 촬영 순서와 모순되지 않는다.
- [ ] Phone과 Watch가 같은 단계 이름 `안정·관찰·주의·위험`을 표시한다.
- [ ] Watch 시작 요청 후에만 `측정·자동 전송 중`이 보인다.
- [ ] Watch를 중지·해제하기 전에는 카메라 측정 컷을 넣지 않는다.
- [ ] 자기설문 결과는 서버 저장 성공 후 표시된 실제 화면이다.
- [ ] 신규 세션은 자기설문 작성/건너뛰기 후 챗봇으로 이동한다.
- [ ] 이미 활성인 세션을 재개한 화면을 신규 자기설문 흐름처럼 편집하지 않는다.
- [ ] 음성 입력으로 보낸 AI 답변만 해당 테이크에서 자동 TTS로 재생된다.

### 데이터와 주장

- [ ] `DEMO/FICTIONAL` 고지가 데이터 화면에서 식별 가능하다.
- [ ] 120일 변화가 단조로운 감소나 개선 서사로 편집되지 않았다.
- [ ] 알림 장면이 실제 서버 이벤트이며 합성 팝업이 아니다.
- [ ] 갈망 단계와 AUQ 점수를 진단·질환 심각도·치료 결과로 부르지 않는다.
- [ ] 앱 사용 전후를 원인과 결과처럼 연결하는 전환·화살표·자막이 없다.
- [ ] 실제 환자, 연구 참여자 또는 운영자 계정의 정보가 없다.
- [ ] 서버 IP, SSH 정보, API 키, 토큰, 비밀번호가 노출되지 않는다.

## 11. 반복 촬영용 계정 수명주기

각 테이크는 다음 순서를 그대로 사용합니다.

1. 서버에서 `DEMO_SCENARIO_ENABLED=true`를 확인하고 백엔드를 재시작합니다.
2. `--dry-run`으로 계획을 확인합니다.
3. `--provision-confirm PROVISION-VP012-DEMO`를 실행합니다. 이 시점에는 정우식 프로필과 동의만 존재하며 과거 기록은 0건입니다.
4. Phone에서 `woosik.jeong@neurotruth.kr`로 로그인합니다. 성공한 로그인 시각을 기준으로 120일 시나리오가 한 번 생성됩니다. 오늘 현재 시각 이전의 Watch 착용 구간, 최근 1시간 예측, 갈망 이벤트, 자기설문, 세션도 함께 생성되어 당일 중첩 막대가 즉시 표시됩니다.
5. 촬영을 마칠 때 앱의 기존 `로그아웃`을 누릅니다. 로그아웃 성공 응답 전에 데모 계정과 관련 기록이 모두 삭제됩니다.
6. 다음 테이크 전에는 3번의 provision 명령을 다시 실행합니다.

앱 강제 종료, 네트워크 단절, access token 만료, refresh는 촬영 종료가 아니며 데이터를 삭제하지 않습니다. 로그인 중 `demo_seed_failed` 또는 로그아웃 중 `demo_delete_failed`가 표시되면 재시도 가능한 서버 오류입니다. 로그인 실패 시 토큰은 발급되지 않고 계정은 다시 로그인할 수 있는 상태로 남습니다. 로그아웃 실패 시 계정도 남으므로 같은 로그아웃 동작을 다시 시도합니다.

과거와 당일 중첩 막대는 주로 Watch를 착용한 아침·점심·저녁 구간만 채우며 미측정 시간은 빈 구간입니다. 120일 중 6일에만 드물게 수면 중 착용 구간이 포함되고, 해당 수면 구간에서는 합성 알림을 만들지 않습니다. 하루 24시간 전체를 측정한 것으로 표시하지 않습니다. 이벤트는 하루 2~10건, 15분 이상 간격으로 배치하고 각 이벤트에 AUQ 기록을 연결합니다. 모두 합성 데모 기록이며 임상적 빈도나 중증도를 뜻하지 않습니다.

앱에서 로그아웃할 수 없는 장애 복구 상황에만 다음 확인형 CLI를 사용합니다.

```text
python -m app.maintenance.seed_vp012_demo --delete-confirm DELETE-VP012-DEMO
```
